## 3. 闭卷十题（优先练）

### Q1：Vue vs React 心智差异是什么？

**口述：**

都是声明式 UI。Vue 靠 Proxy/响应式追踪依赖，改数据后精确通知订阅者；React 靠「`setState`/props 变 → 组件函数重跑 → reconcile → commit」。工程上 React 强调**不可变更新**和**渲染纯度**；Vue 更接近可变数据模型。

补充：React 不自动追踪依赖，是为了模型简单、易推理、易做可中断的并发渲染；代价是依赖数组与闭包要自己管。Fiber = 可中断工作单元 + 优先级，支撑 `startTransition`。18+ 自动批处理扩到 Promise/定时器；基于上次结果用函数式更新。

**回链：** [01](./01-思维模型与Vue对照.md)

---

### Q2：Fiber / 批处理怎么讲？

**口述：**

- **Fiber**：协调算法与工作单元结构，把更新拆成可中断小任务，高优先级（输入）可插队，支撑并发特性。面试点到「可中断 + 优先级」即可，不必背源码。
- **批处理**：同一事件里多次 `setState` 合并成一次渲染；18+ 在 Promise、`setTimeout`、原生事件里也默认 batch。要中间态才 `flushSync`（慎用）。多数业务用 `setX(x => …)` 即可。
- **Render / Commit**：Render 算下一棵树（可中断，须纯）；Commit 刷 DOM（偏同步）。副作用放 Effect，不放 render。

**回链：** [01](./01-思维模型与Vue对照.md) · [10 补遗 Q1/Q5](./10-工作上手清单与面试索引.md)

### Q3：key 的真实作用是什么？

**口述：**

同级 diff 时标识「是不是同一个节点」。稳定 key → 复用 DOM 与组件状态；错误 key（如 index，且列表会插入/删除/排序）→ 状态错位。列表项有本地 state（展开、输入）时尤其要命。

另：故意重置一块 UI 状态，给组件换 `key`（如 `key={userId}`）比手动清一堆字段干净。Diff 同层比较、类型不同则拆旧建新、靠 key 对齐列表，不做完整跨层匹配。

**回链：** [02](./02-JSX组件与渲染.md)

---

### Q4：Hooks 顺序与闭包陷阱？

**口述：**

- **顺序**：每个组件 Fiber 上按调用顺序挂 Hook 链表；每次渲染按同序取第 n 个。条件/循环里调 Hook 会错位 → 顶层、同序。
- **闭包陈旧**：异步回调 / Effect 捕获了某次渲染的 props/state。解法：函数式更新；依赖写全；`useRef` 存最新；或用 `useEffectEvent`（订阅稳、读取新）。
- **稳引用 ≠ 跟更新绑定**：`useCallback` 空依赖拿到的是旧闭包；要最新值就加依赖、函数式更新，或 EffectEvent。
- **Effect vs LayoutEffect**：绘制后异步 vs DOM 更新后绘制前同步；量尺寸、防闪烁用 layout。

**回链：** [03](./03-Hooks核心.md) · `疑问点.md`（useEffectEvent / 闭包）

---

### Q5：Effect 职责与请求竞态？

**口述：**

Effect 表达「同步外部系统」（订阅、定时器、命令式 DOM），不是 onMounted/watch 万能桶。派生数据在渲染期算（≈ Vue computed）；点击发消息走事件。

**请求不该默认进 Effect**：还要缓存、去重、重试、失效；手写易漏竞态。新代码优先 Query / loader / RSC。

**竞态**：先发后至，旧响应覆盖新 UI。解法：`AbortController`、cancelled 标志、Query 切 `queryKey` 自动取消。StrictMode 开发态 mount→cleanup→mount，暴露漏清理；生产不双调，别删 StrictMode。

| 必须用 Effect | 不该用 Effect |
|---------------|---------------|
| WebSocket / interval / 同步 video DOM | 拼 fullName、filter 列表、默认列表请求 |

**回链：** [05](./05-副作用与数据获取.md)

### Q6：TanStack Query 怎么分层讲？

**口述：**

- **服务端状态**：真相在后端，需缓存与过期（列表、用户资料）→ Query。
- **客户端状态**：仅 UI（弹窗、向导步）→ useState / Zustand。
- **queryKey**：包含影响结果的全部参数（id、筛选、分页）；同 key 共享缓存。
- **失效**：mutation 成功后 `invalidate` 或 `setQueryData`；乐观更新配 `onError` 回滚；按页设 `staleTime`。
- **和 Vue**：Pinia ≈ 客户端全局；Query ≈ 独立服务端缓存层；Nuxt `useFetch` 更接近 Query + SSR。

列表页分层：URL 参数 → Query（key 含筛选分页）→ 展示；筛选本地或 search；mutation + invalidate；权限在布局；非必要不进 Redux。

**回链：** [05](./05-副作用与数据获取.md) · [10 Q15](./10-工作上手清单与面试索引.md)

### Q7：memo / transition 边界？

**口述：**

先问「谁在重渲染」，再优化。函数组件默认随父重跑；`memo` + props 浅相等可跳过。

- **不该 memo**：props 每次都变、子树很轻、Compiler 已覆盖；memo 有比较成本。
- **该考虑**：重子树 + 稳定回调/`useCallback` 喂给 memo 子组件；优先理清状态边界、拆组件、虚拟列表。
- **`startTransition`**：非紧急更新降优先级，保输入流畅（大列表过滤不卡打字）。
- **`useDeferredValue`**：对「已有值」做延迟版本，适合派生展示跟输入分离。
- **Compiler**：省手工 memo 样板，不替代错误数据流与虚拟列表。
- **反模式**：巨型 Context、render 里随机 key、整表进 Context、Effect 连环 setState。

**回链：** [06](./06-性能与并发特性.md)

### Q8：Zustand vs Redux vs Context？

**口述：**

| 方案 | 何时用 |
|------|--------|
| Context | 主题/少量跨层；value 不稳会整树刷 |
| Zustand | 新项目默认：API 薄、selector 精细订阅 |
| Redux/RTK | 大型协作、中间件生态、存量项目；会读 slice 即可 |
| Query | 服务端缓存，别塞进 Redux 大对象 |

selector：只订需要的切片；返回新对象字面量每次不相等 → 白渲染；RTK 可用 `shallowEqual` / `createSelector`。全局 Toast 用轻量 store 或专用库，别塞业务大 store。表单多字段用 RHF（ref 注册，减每键全表重渲染）。

**回链：** [08](./08-路由与状态生态.md) · [04](./04-数据流与表单.md)

### Q9：Data Router 比 Component 模式多解决什么？

**口述：**

- **Component 模式**：`<BrowserRouter>` + `<Routes>` / `<Route>`，路由长在组件树里，心智接近 Vue Router 声明式配置。
- **Data Router**：`createBrowserRouter` + `<RouterProvider>`，路由表在组件外；原生支持 lazy、`errorElement`、`HydrateFallback`、`ScrollRestoration`、`useNavigation`（全局导航态）、loader/action 数据 API。

工程上：嵌套 + `Outlet`、params / search / location.state、鉴权布局包一层 + `Navigate`、路由级懒加载减首包。loader 与 Query 不必然冲突——loader 做首屏关键，Query 做客户端缓存与交互刷新，或统一 Query、路由只管参数；团队定一种主路径。

**项目锚点：** airbnb-app 用 Data Router（lazy、errorElement、ScrollRestoration、navigation loading）。

**回链：** [08](./08-路由与状态生态.md) · airbnb-app `src/router`

### Q10：Error Boundary + Suspense + lazy？

**口述：**

- **Error Boundary**：捕获子树**渲染期**错误，展示降级 UI；只能类组件（或库封装）。不捕获事件处理器、异步、Boundary 自身错误。工作中**路由级**包一层，避免整站白屏。
- **Suspense**：组件「等待」时由最近边界展示 fallback；比到处 `if (loading)` 更组合。纯 CSR 数据 Suspense 常需框架/库支持。
- **`React.lazy` + Suspense**：路由级代码分割减首包；Next 有自己的 splitting 与 `loading.tsx`。
- 可顺带：Portal 挂 `body` 但事件沿 React 树冒泡；React 19 函数组件可直接收 `ref`，多数不再需要 `forwardRef`。

**回链：** [10 补遗 Q2–Q4/Q8/Q9](./10-工作上手清单与面试索引.md)

**综合题（列表页）：**

**请求中间件：** 基址、token、错误码、刷新登录；Query 的 `queryFn` 只调封装层（对齐 Vue Axios 拦截器经验）。
